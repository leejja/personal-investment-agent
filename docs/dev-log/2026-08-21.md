## 2. Common Models

구현 파일:

```text
app/models/common.py
```

구현 모델:

```text
RiskLevel
AnalysisConfidence
Evidence
UserRequest
```

### RiskLevel

투자 및 포트폴리오 위험 수준을 표현한다.

```text
LOW
MEDIUM
HIGH
```

### AnalysisConfidence

Agent 분석 결과의 신뢰도를 표현한다.

```text
LOW
MEDIUM
HIGH
```

### Evidence

Agent 판단의 근거를 추적하기 위한 공통 모델이다.

주요 필드:

```text
source
description
reference
timestamp
```

`reference`를 추가하여 향후 다음과 같은 원본 데이터 식별자를 추적할 수 있도록 했다.

```text
OpenDART 공시번호
ECOS 통계코드
뉴스 URL
기타 외부 데이터 reference
```

이는 프로젝트의 핵심 설계 원칙인 **Traceability**를 지원한다.

### UserRequest

Supervisor / Router가 처리할 사용자 요청의 기본 구조다.

주요 필드:

```text
question
symbols[]
```

## 3. Market Models

구현 파일:

```text
app/models/market.py
```

구현 모델:

```text
MarketRegime
MarketIndicator
MarketAnalysis
```

### MarketRegime

현재 시장 환경을 다음 세 단계로 표현한다.

```text
RISK_ON
NEUTRAL
RISK_OFF
```

`MarketRegime`과 `RiskLevel`은 별도의 개념으로 유지한다.

예:

```text
regime     = RISK_ON
risk_level = HIGH
```

위험자산 선호 시장이면서 동시에 시장 위험도가 높은 상황을 표현할 수 있다.

### MarketIndicator

시장 분석에 사용되는 개별 지표를 표현한다.

예상 데이터:

```text
KOSPI
KOSDAQ
S&P 500
NASDAQ
USD/KRW
한국 기준금리
미국 기준금리
외국인 수급
기관 수급
경기선행지수
```

### MarketAnalysis

Market Agent의 최종 분석 결과를 표현한다.

```text
MarketAnalysis
├── regime
├── risk_level
├── summary
├── indicators[]
├── confidence
└── evidence[]
```

Pydantic 객체 생성 및 JSON serialization 테스트를 완료했다.

## 4. Stock Models

구현 파일:

```text
app/models/stock.py
```

구현 모델:

```text
ScenarioType
StockPriceSnapshot
FinancialSnapshot
StockScenario

```

### ScenarioType

개별 종목 전망을 다음 시나리오로 구분한다.

```text
BULL
BASE
BEAR
```

### StockPriceSnapshot

종목의 기본 시장 데이터를 표현한다.

```text
symbol
name
price
change_pct
volume
```

### FinancialSnapshot

v1에서는 핵심 재무지표만 포함한다.

```text
revenue
operating_profit
net_income
per
pbr
roe
```

향후 실제 OpenDART 및 기타 데이터 연동 과정에서 필요한 재무지표를 확장한다.

### StockScenario

Bull / Base / Bear 시나리오를 구조화한다.

```text
scenario
thesis
target_price
probability
```

`probability`는:

```text
0 <= probability <= 1
```

범위로 validation한다.

### StockAnalysis

Stock Research Agent의 최종 분석 결과다.

```text
StockAnalysis
├── symbol
├── name
├── price
├── financials
├── investment_thesis
├── catalysts[]
├── risks[]
├── scenarios[]
├── risk_level
├── confidence
└── evidence[]
```

삼성전자 샘플 데이터를 이용하여 Bull / Base / Bear 시나리오 및 JSON serialization 테스트를 완료했다.

## 5. Portfolio Models

구현 파일:

```text
app/models/portfolio.py
```

구현 모델:

```text
PortfolioPosition
PortfolioContext
InvestorProfile
```

계좌의 객관적인 상태와 사용자의 투자 성향을 의도적으로 분리했다.

### PortfolioPosition

개별 보유 포지션을 표현한다.

```text
symbol
name
quantity
average_price
current_price
market_value
profit_loss
profit_loss_pct
weight
```

내부 포트폴리오 비중은 다음 범위를 사용한다.

```text
0.0 ~ 1.0
```

예:

```text
20% → 0.20
50% → 0.50
```

### PortfolioContext

실제 계좌 상태를 표현한다.

```text
PortfolioContext
├── total_value
├── cash
├── positions[]
└── evidence[]
```

향후 Kiwoom REST API와 다음 형태로 연결할 예정이다.

```text
Kiwoom REST API
        ↓
Kiwoom Service
        ↓
PortfolioContext
```

### InvestorProfile

계좌 데이터와 분리된 투자자의 투자 성향 및 제약조건을 표현한다.

```text
risk_tolerance
investment_horizon_months
target_return_pct
objectives[]
constraints[]
```

이를 통해 동일한 시장 및 종목 분석이라도 투자자의 실제 상황에 따라 다른 전략을 생성할 수 있도록 한다.

## 6. Strategy Models

구현 파일:

```text
app/models/strategy.py
```

구현 모델:

```text
InvestmentAction
PositionRecommendation
StrategyResult
```

### InvestmentAction

다음 행동을 구조적으로 표현한다.

```text
BUY
ADD
HOLD
REDUCE
SELL
AVOID
```

의미:

```text
BUY     → 신규 포지션 매수
ADD     → 기존 포지션 추가 매수
HOLD    → 현재 포지션 유지
REDUCE  → 일부 비중 축소
SELL    → 포지션 청산
AVOID   → 신규 진입 회피
```

### PositionRecommendation

종목별 투자전략을 표현한다.

```text
symbol
name
action
current_weight
target_weight
rationale
conditions[]
```

단순 BUY / SELL 추천을 넘어 현재 비중과 목표 비중 및 전략 변경 조건까지 표현할 수 있도록 설계했다.

### StrategyResult

Portfolio Strategy Agent의 최종 출력이다.

```text
StrategyResult
├── summary
├── recommendations[]
├── portfolio_risk
├── confidence
└── evidence[]
```

샘플 삼성전자 HOLD 전략을 이용하여 객체 생성 및 JSON serialization 테스트를 완료했다.

## 12. Architecture Decision

외부 API 호출 및 데이터 취득 로직을 Agent 내부에 직접 구현하지 않는다.

기본 방향:

```text
Agent
  │
  ▼
Service
  │
  ▼
MCP / External API
```

이를 통해 다음 책임을 분리한다.

```text
Agent
→ reasoning / investment decision

Model
→ Agent 간 데이터 계약

Service
→ 외부 데이터 접근 및 변환

MCP
→ Agent가 사용할 tool interface

External API
→ 실제 데이터 제공
```

Service와 MCP의 구체적인 관계는 실제 Service Layer 구현 과정에서 다시 검토하고 README Architecture에 반영한다.

첫 번째 대상으로 한국은행 **ECOS Service**를 구현한다.

예상 파일:

```text
app/services/ecos.py
```

초기 방향:

```text
ECOS API
   ↓
EcosService
   ↓
Pydantic Model
   ↓
Test
```

`EcosService`의 책임은 우선 다음 범위로 제한한다.

```text
API request
HTTP error handling
JSON parsing
Response conversion
```

Agent reasoning 로직은 Service에 포함하지 않는다.

HTTP client는 `httpx` 사용을 우선 검토한다.

예상 초기 인터페이스:

```python
class EcosService:
    def __init__(self, api_key: str):
        ...

    def get_statistic(
        self,
        statistic_code: str,
        cycle: str,
        start_date: str,
        end_date: str,
        item_code: str,
    ):
        ...
```

다음 세션에서는 **Service Layer의 역할과 ECOS API 구조를 먼저 확인한 후 `app/services/ecos.py` 구현을 시작한다.**
