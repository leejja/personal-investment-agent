## H. Missing-data / Event semantics

- ROE/Operating Margin이 missing이어도 evaluator는 실행되며, 기존
  `AvailabilityStatus.UNAVAILABLE` semantics를 그대로 사용한다(orchestrator가
  새 fallback을 발명하지 않음).
- 두 evaluator 모두 예외를 던지지 않으므로 orchestrator가 별도 exception
  swallow 로직을 추가하지 않았다 — 예외가 나면 그대로 전파된다(기존 Agent
  layer의 "root 실패=전체 실패" 관례와 일관).
- Forward component coverage는 현재 `coverage_status=INSUFFICIENT`,
  `critical_path_satisfied=False`(기존 4-family 전부 CRITICAL, 등록 feature
  0개라는 기존 registry 상태의 정직한 반영, 신규 판단 아님).
- `event_path_availability`는 기존 default `UNKNOWN`을 그대로 사용 — Event
  Intelligence가 아직 없으므로 임의로 값을 지정하지 않았다.
- Event evidence 평가가 이미 조립된 Forward `ComponentAssessment`를 mutate하지
  않음을 deep-copy 비교로 재확인했다(`test_future_opportunity_evidence_does_not_mutate_forward_component_assessment`).
