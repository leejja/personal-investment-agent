**Why NEXT**: final decision path에서 계약이 없는 가장 upstream 지점이며,
현재 repository evidence(raw/derived slot, directionality, evaluation_basis,
`PolicyConfigRef`, `EvaluationContext.policy_config_ref/peer_group_ref`)만으로
설계 가능하다. 이 contract 없이 Family Score/Component Score/Signal/Core
Attractiveness의 의미를 설계하면 각자 다른 가정으로 갈라질 위험이 있다.

NEXT의 future design scope(이번 pass에서 설계하지 않음):

```text
A. normalized_value production ownership
B. normalization input boundary (raw/derived value, directionality,
   evaluation basis, PolicyConfigRef, peer-group/reference context 경계)
C. normalized_value representation semantics (direction 적용 여부,
   scale convention의 구조적 형태, None/INVALID/NOT_APPLICABLE 의미)
D. PolicyConfig boundary (versioned config 책임, code constant와의 경계)
E. explicit OPEN items (feature별 normalization method, numeric parameter,
   threshold, weight, peer-relative basis, calibration dataset)
```

NEXT non-goals: numeric threshold/normalization parameter/score weight 결정,
PER/PBR 적정 범위, feature별 calibration, historical backtest/walk-forward,
evaluator 신규 구현·수정, normalization 구현, Core Attractiveness 구현,
Policy Step 2+ 구현, SOA production, Portfolio Strategy 변경.

**Why SECOND**: normalization contract가 있어도 numeric 값의 출처가 없으면
Score/Signal/Core는 비어 있다. SECOND는 NEXT가 정한 representation/basis를
기준으로 필요한 calibration evidence(point-in-time dataset, historical
valuation, disclosure timing/as-of, price adjustment/corporate action,
backtest/walk-forward feasibility, parameter provenance, leakage risk)를 현재
data source로 확보할 수 있는지 조사한다 — calibration implementation이
아니다. 감사 범위가 NEXT 결과에 의존하므로 SECOND다.
